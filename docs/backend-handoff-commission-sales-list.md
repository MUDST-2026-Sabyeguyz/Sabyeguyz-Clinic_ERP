# Handoff: รายการขายในหน้าปิดรอบคอมมิชชัน

## อาการ

หน้าปิดรอบคอมมิชชันแสดงยอดฐานคำนวณ **฿50,500** และค่าคอมมิชชัน **฿2,525** แต่รายการขายและหน้าต่างยืนยันปิดรอบกลับแสดง **0 รายการ** ทำให้ผู้จัดการตรวจสอบรายการก่อนปิดรอบไม่ได้

## งานที่ขอให้ตรวจและแก้

ตรวจ API รายงานเดิมที่ frontend ใช้อยู่:

`GET /api/commission/report?from=YYYY-MM-DD&to=YYYY-MM-DD`

ขอให้แก้เฉพาะจุดที่จำเป็นใน backend ให้ response ของ API เดิมมีรายละเอียดรายการขายที่ใช้คำนวณยอดของรอบนั้นครบถ้วน โดยไม่สร้าง endpoint ใหม่ และไม่เปลี่ยนสูตรหรือขอบเขตการคำนวณค่าคอมมิชชันโดยไม่จำเป็น

## รูปแบบข้อมูลที่ frontend ใช้

API ส่ง array ของรายงานตามผู้ขาย/สาขา โดยแต่ละแถวมี `branchCode`, `saleCount`, `base`, `rate`, `commission` และ `sales` ซึ่งเป็น array ของรายการขาย เช่น:

```json
[
  {
    "staffId": 12,
    "staffName": "ชื่อพนักงาน",
    "branchCode": "BR01",
    "branchName": "สาขาตัวอย่าง",
    "saleCount": 1,
    "base": 50500,
    "rate": 0.05,
    "commission": 2525,
    "sales": [
      {
        "id": 123,
        "saleDate": "2026-11-15",
        "receiptNo": "R-001",
        "courseNo": "C-001",
        "courseName": "คอร์สตัวอย่าง",
        "sellerName": "ชื่อพนักงาน",
        "gross": 52000,
        "lineDiscount": 1500,
        "commissionableAmount": 50500,
        "completedRefund": 0
      }
    ]
  }
]
```

frontend อ่านรายการจาก `row.sales` และรวมจำนวนรายการจากทุกแถวหลังกรอง `branchCode` ให้ตรงกับสาขาที่เลือก ดังนั้น `sales` ต้องไม่หายจาก JSON หรือถูก serialize เป็น `null` เมื่อมีรายการที่ร่วมคำนวณ

## จุดตรวจรับ

- เรียก API เดิมด้วยช่วงวันที่ของรอบที่มีปัญหา และตรวจว่าแถวในสาขานั้นมี `sales` พร้อมรายละเอียดขาย
- จำนวน `saleCount` ของแต่ละแถวตรงกับ `sales.length`
- ยอด `base` ของแถวสอดคล้องกับยอดฐานจากรายการขายตามกฎเดิม รวมถึงส่วนลดและ refund ที่เกี่ยวข้อง
- เมื่อ API ตอบถูกต้องแล้ว จำนวนรายการใน frontend และหน้าต่างยืนยันปิดรอบต้องไม่เป็น 0 หากมีรายการขายในรอบ
- หาก source ปัจจุบันมี `sales` อยู่แล้ว ให้ตรวจ response จาก backend ที่กำลังให้บริการก่อนแก้ logic เพิ่ม เพราะอาจเป็น runtime/build เก่าที่ยังไม่ใช้ response shape ล่าสุด

## ขอบเขต

แก้ backend/API เดิมเท่าที่จำเป็น ไม่เพิ่ม API ใหม่ ไม่แก้ frontend, Docker หรือ schema ฐานข้อมูลในงานนี้ และยังไม่ต้อง commit หรือ push งานขึ้น GitHub
