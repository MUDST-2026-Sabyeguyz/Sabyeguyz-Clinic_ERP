# ติดตั้งการซิงก์ Google Calendar บนเซิร์ฟเวอร์จริง

เอกสารนี้ต่อจาก [google-calendar-sync.md](google-calendar-sync.md) (ซึ่งอธิบายการสร้างปฏิทินและ service account) ใช้กับการติดตั้งแบบ Docker Compose ที่ `compose.yaml`

## สิ่งที่ต้องมีก่อน
- ระบบรันด้วย Compose ได้อยู่แล้ว (`deploy/README.md`) และมี `.env` ที่ตั้ง `POSTGRES_PASSWORD`, `JWT_SECRET` แล้ว
- บัญชี Gmail กลาง ปฏิทินของแต่ละสาขา (พระราม 9, แบริ่ง) และ service account ตามคู่มือ Google Calendar
- ไฟล์คีย์ JSON ของ service account และปฏิทินทั้งสองแชร์ให้อีเมลของ service account ด้วยสิทธิ์ "ทำการเปลี่ยนแปลงกิจกรรม"
- เซิร์ฟเวอร์ออกอินเทอร์เน็ตไปที่ Google (`oauth2.googleapis.com`, `www.googleapis.com`) ได้

## ขั้นตอน
1. **วางไฟล์คีย์บนเซิร์ฟเวอร์** ในโฟลเดอร์ที่อยู่นอกโปรเจกต์ เช่น `/opt/sabyeguyz/secrets/calendar-sync-key.json` ให้ผู้ใช้ที่รัน Docker อ่านได้เท่านั้น (`chmod 600`) ห้ามใส่ในโฟลเดอร์ของ repository และห้ามส่งทางแชท/อีเมล
2. **เพิ่มบรรทัดนี้ใน `.env`** ของเซิร์ฟเวอร์ (ที่อยู่ไฟล์ตามข้อ 1):
   ```
   CALENDAR_KEY_FILE=/opt/sabyeguyz/secrets/calendar-sync-key.json
   ```
3. **ตรวจไฟล์คีย์ก่อนเปิดระบบ** (ไม่พิมพ์รหัสออกมา) ใส่ Calendar ID ของทั้งสองสาขา:
   ```
   echo "APP_CALENDAR_SERVICE_ACCOUNT_KEY_FILE=$CALENDAR_KEY_FILE" > .env.calendar
   bash backend/scripts/calendar-check.sh <CalendarID-พระราม9> <CalendarID-แบริ่ง>
   ```
   ต้องขึ้น `ALL GOOD` (สคริปต์ใช้ `openssl` และ `curl`)
4. **เปิดระบบพร้อมการซิงก์:**
   ```
   docker compose -f compose.yaml -f compose.calendar.yaml up -d --build
   ```
   ถ้าไม่ใส่ `-f compose.calendar.yaml` การซิงก์จะปิด ระบบทำงานเหมือนเดิม และถ้าลืมตั้ง `CALENDAR_KEY_FILE` Compose จะไม่ยอมเริ่มพร้อมข้อความบอกสาเหตุ
5. **ผูกปฏิทินกับสาขา** ล็อกอินเป็น Manager แล้วไปเมนู **ปฏิทิน Google** วาง Calendar ID ของแต่ละสาขา กดบันทึก (ทำครั้งเดียว ข้อมูลอยู่ในฐานข้อมูล)
6. **ตรวจว่าทำงาน** ในหน้าเดียวกันกด **ซิงก์ทันที** ควรขึ้นผลซิงก์ และสถานะแต่ละสาขาเป็น "รอซิงก์ 0, ล้มเหลว 0" จากนั้นลองจองนัดทดสอบแล้วดูว่าขึ้นในปฏิทินของสาขา

หลังจากนี้ระบบซิงก์เองทุกประมาณ 30–60 วินาที ไม่ต้องกดอะไร

## ต้องตัดสินใจก่อนใช้ข้อมูลจริง: รหัสสาขา
รหัสสาขาในข้อมูลตัวอย่างคือ `01` = สาขาพระราม 9 และ `02` = สาขาแบริ่ง และรหัสสาขา **ถูกฝังอยู่ใน HN ของคนไข้** (รูปแบบ ปี + รหัสสาขา + เดือน + ลำดับ เช่น `2601100001`) ถ้ารหัสจริงของคลินิกต่างจากนี้ ต้องตกลงและตั้งรหัสให้ถูกก่อนเริ่มลงทะเบียนคนไข้จริง เพราะแก้ภายหลังจะไม่ตรงกับ HN ที่ออกไปแล้ว การซิงก์เองไม่ขึ้นกับรหัสนี้ (ผูกด้วยรหัสสาขาในหน้าตั้งค่าเท่านั้น)

## ปิดหรือถอยกลับ
- ปิดการซิงก์: รัน Compose โดยไม่ใส่ `-f compose.calendar.yaml` (นัดที่อยู่ใน Google เดิมยังอยู่ ไม่ถูกลบ)
- เลิกซิงก์เฉพาะสาขา: ในหน้า **ปฏิทิน Google** เว้นช่อง Calendar ID ว่างแล้วบันทึก
- ถ้าสงสัยว่าคีย์รั่ว: ลบคีย์ใน Google Cloud (Service Accounts > Keys) แล้วสร้างคีย์ใหม่ วางทับไฟล์เดิมและรีสตาร์ต backend

## แก้ปัญหาเบื้องต้น
| อาการ | สาเหตุที่น่าจะเป็น |
|---|---|
| `ล้มเหลว` มากกว่า 0 | Google ติดต่อไม่ได้ หรือปฏิทินไม่ได้แชร์ให้ service account (รัน `calendar-check.sh` ดู) |
| ขึ้น 403 ตอนเขียน | สิทธิ์ที่แชร์เป็นแค่ "ดู" ต้องเป็น "ทำการเปลี่ยนแปลงกิจกรรม" |
| ขึ้น `invalid_grant` ตอนล็อกอิน | ไฟล์คีย์ผิดหรือถูกลบใน Google Cloud |
| ปุ่ม "ซิงก์ทันที" กดไม่ได้ | เซิร์ฟเวอร์ยังไม่ได้เปิดการซิงก์ (ลืม `-f compose.calendar.yaml`) |
